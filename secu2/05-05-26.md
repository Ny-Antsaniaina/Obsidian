# SECU2 : Intégrité - Confidentialité

## 1. CONFIDENTIALITÉ

### A. Chiffrement Symétrique

Le chiffrement symétrique utilise **une seule clé partagée** (sAB) entre les deux parties.

#### Chiffrement de César

- Substitution simple : décalage de chaque lettre de l'alphabet
- Exemple : décalage de 3 → A→D, B→E, C→F...
- **Faible sécurité** (seulement 25 clés possibles)

#### AES (2000) — _Advanced Encryption Standard_

Basé sur les principes de **Shannon** :

- **Confusion** : relation complexe entre clé et chiffré (non-linéaire, via S-Box)
- **Diffusion** : chaque bit du message affecte tout le chiffré (via permutations)

---

### B. Chiffrement Asymétrique

Deux clés distinctes : **clé publique** (partageable) et **clé privée** (secrète).

```
A ──────────────────────────────► B
  clé publique de B (Crypto)       (Stégano)
```

Exemples d'usage :

- **A** : chiffrement avec la clé publique de B
- **B** : déchiffrement avec sa clé privée

---

### C. Échange de clé — Diffie-Hellman (années 70)

**Problème** : comment partager sAB de façon sécurisée sur un canal non sécurisé ?

**Principe** : chacun génère une clé privée (sA, sB), et on combine les clés publiques pour arriver au même secret partagé, sans jamais l'envoyer.

```
sAB = sA ∩ sB   (combinaison des secrets individuels)
```

---

### D. ECDH — Elliptic Curve Diffie-Hellman

Comme illustré dans l'exercice de l'image :

|Étape|Description|
|---|---|
|1|Accord sur la courbe elliptique **y² = x³ + 2x + 3 (mod 97)** et le point de base **G(3,6)**|
|2|Chacun choisit sa **clé privée** (a ou b)|
|3|Chacun calcule sa **clé publique** (A = a·G ou B = b·G) et l'échange|
|4|Chacun calcule **S = a·B = b·A** → même point secret|

**Exemple de l'exercice :**

```
Moi        : a = 25  →  A = 25·G = (80, 10)
Camarade   : b = 17  →  B = 17·G = (87, 70)

Point secret S :
  Moi      : S = 25 · (87,70) = (32, 90)  ✓
  Camarade : S = 17 · (80,10) = (32, 90)  ✓
```

> La courbe y² = x³ + 7 (Bitcoin) fonctionne sur le même principe, avec p beaucoup plus grand.

---

### E. Handshake — Établissement de sAB

Le **handshake** permet d'établir la clé symétrique sAB de façon sécurisée, via :

|Protocole|Principe|
|---|---|
|**ECDH**|Courbes elliptiques (rapide, clés courtes)|
|**RSA**|Factorisation de grands nombres (plus lourd)|

```
Phase 1 (Asymétrique)  →  échange de sAB via ECDH ou RSA
Phase 2 (Symétrique)   →  communication chiffrée avec AES
```
